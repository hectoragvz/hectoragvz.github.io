Reinforcement learning · WebAssembly

Pufferosaurus

A tiny recurrent policy learned to jump over cacti. The model, game simulation, and rendering all run locally in your browser—there is no inference server behind the demo.

Live demo

The agent plays autonomously and restarts on collision.

Everything above is C compiled to WebAssembly, including the trained policy and its recurrent state.

What the agent sees

Each frame is reduced to five numbers: the dinosaur’s normalized height and vertical velocity, the horizontal distance to the next obstacle, and that obstacle’s width and height. It never receives pixels or hand-authored timing rules.

What it can do

The action space has only two choices: do nothing or jump. A small MinGRU policy carries state from one frame to the next, then selects one of those actions from the current observation and its memory.

How it learned

Passing a cactus earns +1, colliding costs −1, and each jump costs −0.05. The jump penalty discourages frantic jumping without prescribing when a jump should happen. Training ran for 10 million environment steps with PufferLib; the browser loads the resulting checkpoint directly.

From training loop to game loop

During training, thousands of environment copies advance as fast as possible. This showcase runs one copy at the browser’s animation rate. The same observations, actions, reward rules, physics, network dimensions, and binary checkpoint format are used in both places, so publishing the demo required no retraining.

Inside the browser

Emscripten compiles the C environment, PufferNet inference, and raylib renderer into WebAssembly. The page isolates that runtime in a same-origin iframe. Textures and weights are preloaded into its virtual filesystem, and every animation frame performs inference, advances the simulation, and renders the result on the canvas.

Limits and next steps

This first version intentionally keeps the trained task fixed: one obstacle type, one speed, autonomous playback, and a roughly 2.7 MB generic resource bundle. Future iterations may let visitors inject obstacles or change the playback speed, followed by tighter asset packaging.
